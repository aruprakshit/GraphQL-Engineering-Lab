# RFC 0000: Feature title

Status: Template - not a proposal or an approved decision.

Copy this file to a numbered feature name before proposing a substantial change. Replace every placeholder, remove these instructions and link the RFC from the design guide when discussion begins. A proposal is not evidence that implementation exists.

## Metadata

- Status: Proposed / Accepted / Rejected / Superseded
- Author: [name]
- Date: [date]
- Related issue or PR: [link]
- Decision owner: [name]
- Implementation state: Not started / In progress / Complete
- Validation state: Not run / Partial / Verified, with evidence

## Problem

What concrete behavior or limitation needs to change? Give an example from the current system.

## Goals and non-goals

What outcome must this proposal deliver? What work is intentionally outside its scope?

## Current behavior

Link to relevant code, tests and architecture views. Distinguish observed evidence from assumptions.

## Options considered

Compare at least the realistic alternatives, including retaining the current behavior where appropriate. Explain their consequences for this project.

## Proposed design

Describe responsibilities, boundaries and the request/data flow. Link a rendered diagram if needed. Specify API contracts, nullability, errors, identity sources and resource limits only where relevant.

## Failure behavior and security

Explain unavailable dependencies, invalid input, partial success, cancellation and data exposure as applicable. State which existing protections the design relies on.

## Compatibility and migration

Describe existing clients/data, additive or breaking changes, backfill/index needs, deployment order and rollback. If none apply, explain why.

## Verification plan

Identify meaningful unit, integration, HTTP or load checks and the evidence that would establish success. Define expected results before declaring the work verified.

## Delivery checkpoints

Break implementation into small reviewable commits with an observable result for each. Include documentation and diagram updates.

## Risks and open questions

List unresolved choices, their impact and what evidence or decision will resolve them.

## Decision outcome

Leave empty while Proposed. On a real decision, record who decided, when, the selected option and the reason. Link the resulting ADR if appropriate.
